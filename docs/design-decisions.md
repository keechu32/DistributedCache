# Design decisions

1. **Preserve the original cache engine.** The HashMap plus custom doubly linked list remains visible and testable. A synchronized cache protects both structures as one invariant. Replacing only the map with a ConcurrentHashMap would not make the list safe.
2. **Simple bounded text protocol.** Newline framing makes manual demonstrations easy. Values allow spaces and Unicode, while frame length, connection count and timeouts bound common resource usage. A length-prefixed binary protocol would be the next step for binary values and more precise byte limits.
3. **Immutable ring with virtual nodes.** SHA-256 provides deterministic token placement across JVMs. Sorting node identifiers makes construction independent of configuration order. Duplicate nodes, empty membership and token collisions fail explicitly. The movement test checks that expansion moves keys only to the added node, not between existing nodes. Migration is a separate problem from placement.
4. **Synchronous replication with honest partial failure.** Success waits for all configured replicas. Local mutation precedes replication, so failure cannot imply rollback. A primary-wide lock enforces order without a sequence log but limits throughput and permits slow replicas to block reads. Asynchronous replication would require a bounded backlog, observability, retry semantics and recovery before claiming reliable delivery.
5. **Shared TTL deadlines.** Forwarding relative TTL after a network delay would extend replica lifetimes. Absolute deadlines preserve intent, subject to wall-clock skew. Clock jumps remain a limitation; persisted deadlines and monotonic local timers would require additional design.
6. **No automatic failover.** Promoting a replica after a timeout without fencing or consensus risks split-brain. The router returns an availability error instead. Replicas demonstrate write propagation; this project does not claim high availability or durable storage.
7. **Repeatable measurement.** JMH forks and warmup reduce JVM measurement mistakes. Raw results and exact run settings are included. TCP workloads reuse connections after setup and include serialization, parsing and round trips; they must not be compared directly with local cache microbenchmarks as if they measured the same operation.
8. **Explicit scope.** The six README phases and final validation are implemented. Persistence, authentication, live membership changes and full replica recovery remain future work rather than unfinished hidden promises.
